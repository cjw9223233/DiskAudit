# 文件分層使用指南

> 改寫自 sps-workstation 專案的同名文件；已把 SPS 專屬的三個例子改成通用例子，其餘維持原文。

給自己與「全新對話」看的：資訊分幾層、什麼時候寫哪裡、什麼時候不要寫。

## 1. 一圖看懂

| 層 | 檔案 | 放什麼 | 誰更新／何時 |
|---|---|---|---|
| 規則 | `CLAUDE.md`（約 10 行） | 長期規則、安全守則 | 規則改變才改 |
| 進度 | `handoff.md` | 當前階段快照；第一行是「回來第一個動作」 | 階段完成時**覆寫** |
| 待辦 | `BACKLOG.md` | 新想法／待辦／技術債，一行一條 | 隨時追加、完成就刪 |
| 記憶 | `~/.claude/projects/.../memory/` | 使用者偏好、環境位置、已定案不重提 | 階段完成時整理一次 |
| 歷史 | git | 每個版本的檔案與原因 | 使用者要求時 commit／打 tag |

原則：同一件事只放一處，其餘用指向（例如 handoff 只寫「規則見 CLAUDE.md」）。

## 2. 使用教學（對 Claude 說什麼）

- 開新對話：「先讀 handoff.md」。
- 中途冒出想法：「記進 BACKLOG」，Claude 只追加一行，不展開、不打斷主線。
- 階段完成：「覆寫 handoff」。
- 要存檔：「commit」（要打版本點就說「打 tag」）。

BACKLOG 一行格式：

```
- [P2] 稽核報表預設輸出位置改放範圍外 — 需改 Invoke-DiskAudit.ps1，發版前決定
```

P1＝擋住主線、P2＝上線前最好做、P3＝有空再說。

## 3. 情境表

| 情境 | 動作 | 寫到哪 |
|---|---|---|
| 開工 | 讀 handoff 第一行，做那件事 | 不寫 |
| 中途冒出新想法 | 一行帶優先度 | BACKLOG |
| 下班或換對話 | 更新「回來第一個動作」與進度 | handoff |
| 階段完成 | 覆寫 handoff、刪 BACKLOG 完成項、整理記憶、commit／tag | 全部 |
| 踩到坑（行不通的方法） | 一兩句寫原因 | handoff §6；跨專案通用的才進記憶 |
| 規則改變 | 改那一行 | CLAUDE.md |
| 出事故（如誤覆寫既有檔案） | 經過寫 handoff，防再犯的規則寫 CLAUDE.md | handoff + CLAUDE.md |
| 要推到遠端前 | 先檢視 handoff、docs 是否含路徑、使用者名稱、主機名稱等敏感資訊；只推私有倉庫 | 不寫 |

## 4. 適用時機

多天、多對話、牽涉線上風險、需要交接給全新對話的專案。一次性的小任務不需要。

## 5. 避免過度使用

| 警訊 | 對策 |
|---|---|
| `CLAUDE.md` 超過約 15 行 | 瘦身：只留長期且每次都要遵守的規則 |
| `handoff.md` 變成流水帳 | 覆寫，不追加；只寫全新對話推不出來的 |
| `BACKLOG.md` 一條超過一行 | 你在展開了，砍成一行 |
| 記憶裡有 repo 查得到的事（程式結構、git 歷史） | 刪掉 |
| 每個小修改都更新四份、都 commit | 不必；階段完成再一起整理 |
| 同一件事寫在兩處 | 留一處，另一處改成指向 |

## 6. 階段完成檢查清單

1. 覆寫 `handoff.md`（含新的「回來第一個動作」）。
2. 刪 `BACKLOG.md` 已完成項，重新排 P1。
3. 整理記憶（`consolidate-memory`）。
4. 使用者要求時 commit，必要時打 tag。
